Agent 卡死的 5 种模式

上一节那条漂亮的 ReAct 链路是“样板间”。真上线跑三个月，你会把这五种翻车姿势看个遍——先认识它们，才不会半夜被客服群炸醒。

一张总保单：五道工程护栏

五种翻车对应的护栏，其实就五条，加进 Agent 的运行框架里：

护栏防什么怎么设（参考值）
循环上限死循环单任务最多 8-10 轮，超限强制收口或转人工
输出截断话痨跑偏单次回复限 300 字，超限截断重来
超时控制系统卡死单次工具调用 10 秒超时，整单 2 分钟封顶
中断恢复半路崩盘每步结果落库，崩了从断点续跑，不从头烧 Token
转人工闸口一切兜不住的情况连续 2 轮无进展 / 客人情绪激烈 / 涉及钱，自动转
记住一个心态：Agent 一定会翻车，工程的意义是让翻车“可控、可查、可恢复”。追求不出错不如追求错得起——这五道护栏就是你的“错得起”。
📌 本节要点
  • 五种翻车：死循环、幻觉工具、参数格式错、信息不足硬答、系统异常没兜底。
  • 根因都指向脚手架：翻车不怪模型怪框架——护栏是工程问题，不是算法问题。
  • 五道护栏：循环上限、输出截断、超时控制、中断恢复、转人工闸口。
  • 转人工不是失败：它是设计的一部分——好 Agent 知道自己什么时候该认输。

上下文工程：给 AI 的“交接班记录”

前三篇解决了“一块白板”的问题。进阶篇面对的是多块白板之间——跨班次、跨 Agent、跨天的信息怎么不丢、不乱、不重复。

概念实战7 分钟
交接断层的三个典型现场
  • 客服转人工：客人跟 AI 聊了 20 分钟，转人工后客服第一句“您说下情况”——客人原地爆炸（3-8 节讲过要带摘要，这就是上下文工程的应用）。
  • Agent 接力：选品 Agent 定好款，文案 Agent 拿到手的却是“写个针织衫文案”——卖点、禁忌、人群全丢了（3-10 节讲的结构化交接就是解药）。
  • 跨天任务：昨天让 AI 分析到一半的数据，今天重开窗口从头再来——昨天的“思考过程”全烧掉了。

这三个现场的病根是同一个：信息只存在一块白板上，换块白板就清零。上下文工程就是给业务流设计“交接班记录”——像餐厅交接班一样，下一棒接手时该知道什么，写清楚、传到位。

交接记录的坏与好
❌ 坏交接：把整本流水账甩过去
【交接内容】前 20 轮完整聊天记录原文…… 下一个 Agent 拿到 3000 字流水，关键信息埋在废话里，还白烧一轮 Token——等于没交接。
✅ 好交接：结构化摘要卡
{ 客人: “王女士”, 诉求: “裙子换小码”, 进度: “已查库存S缺货M有货”, 待办: “等客人选M或等补货”, 情绪: “平和”, 禁忌: “无” } 六个字段，下一棒 3 秒读完，直接续上节奏。
设计交接卡的四要素
  • 事实：已确认的信息（订单号、款号、价格）——写结论，不写过程。
  • 进度：办到哪一步了——让下一棒知道从哪接，不从头问。
  • 待办：下一步要做什么、等谁拍板——交接的核心就是这个字段。
  • 雷区：客人的禁忌和情绪状态——避免下一棒一脚踩雷。
判断你的交接设计好不好，一个标准：换个“人”接手，能不能不问任何一句就接着干？能，交接合格；不能，字段补齐。这个标准对 AI 和人类员工一视同仁——上下文工程本质是把“带团队”的经验写进了系统。
📌 本节要点
  • 交接断层三现场：客服转人工、Agent 接力、跨天任务——病根都是“换白板清零”。
  • 交接卡四要素：事实、进度、待办、雷区——写结论不写流水。
  • 结构化 > 自然段：JSON 摘要卡 3 秒读完，流水账 3000 字白烧 Token。
  • 验收标准：接手方不问一句就能续上，才算合格。

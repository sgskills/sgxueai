第二篇章 · 业务流智能体设计

Skill：把 SOP 喂给 Agent

你团队里最强的运营分析一个产品转化下滑，有一套固定打法——这套打法写成文档，就是 Agent 的 Skill。这一节解剖一个真实 Skill 的骨架。

实战概念8 分钟
为什么需要 Skill 这层东西

一个链接的转化率连续两周往下掉。没有 Skill 的 Agent 怎么分析？看心情——今天怪主图、明天怪价格、后天让你换详情页，全看白板上当时装着什么。跟没有方法论的新运营一模一样：会看数据，没套路。

Skill 就是给 Agent 装的“套路”：一份结构化的流程说明书，告诉它什么情况走什么流程、每步用什么工具、红线在哪。写一次，Agent 每次遇到同类任务都照章执行——这就是把金牌运营的经验变成组织的资产，跟你带团队做 SOP 沉淀是同一个动作。

解剖 · 一个“产品优化诊断” Skill 的骨架

点开每个部分，看它写什么、为什么这么设计：

SKILL.md · 产品优化诊断（product-optimization-analysis）
好 Skill vs 坏 Skill
  • 好 Skill 给判断标准，坏 Skill 给模糊要求：“分析一下为什么卖得不好”是废话，“先拉 30 天数据→对比类目均值→按漏斗定位病灶层”才是标准。
  • 好 Skill 写清边界，坏 Skill 只写流程：样本不足不下结论、只出诊断不动手改价——不写边界，Agent 就敢拿着三天数据让你砍品。
  • 好 Skill 会被迭代：每次复盘把验证过的新打法补进 Skill——它是活的 SOP，不是写完就进棺材的文档。
把你团队最常用的三个分析套路找出来——产品体检、活动复盘、推广诊断——它们就是你 Agent 化的第一批 Skill。写 Skill 这件事，运营操盘手比程序员写得好，因为关键是业务判断，不是代码。
📌 本节要点
  • Skill = Agent 的 SOP：结构化流程说明书，写一次，次次照章执行。
  • 骨架五段：触发条件 → 流程步骤 → 工具指引 → 红线边界 → 兜底转人工。
  • 好 Skill 给判断标准：具体步骤 + 明确边界 + 持续迭代，三样缺一不可。
  • 运营写 Skill 比程序员强：沉淀的是业务判断，代码只是载体。

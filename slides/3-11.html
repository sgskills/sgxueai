权限与安全：AI 能改价吗？

2-4 节防的是“客人骗 AI”，这一节防的是“AI 自己被授权太多”。落地最后一道安全题：给 AI 的权限清单怎么划。

安全实战7 分钟
一个权限判据：错了能撤回吗

给 AI 授权不用纠结，一个判据走天下：这个动作做错了，能不能低成本撤回？

  • 能撤回 → 可以自动：回复客人、查数据、生成文案草稿——错了改一条就行。
  • 撤回有代价 → 人工确认：发优惠券、建退款单、改库存——错了要追损，AI 提议、人拍板。
  • 撤不回 → 永不授权：改价格、转账、删数据、对外发公告——出了事就是资损和舆情，这些按钮永远在人手里。
五种权限模式速查
动作权限模式理由
回复客人咨询全自动说错了下一句可以圆回来
查订单 / 库存 / 物流全自动只读操作，查错无损
生成文案 / 图片草稿全自动草稿不上架，质检兜底
发优惠券 / 建工单人工确认涉及钱和承诺，AI 提议人拍板
改库存 / 上下架商品人工确认误操作影响在售链接
改价 / 退款 / 转账永不授权资金动作，撤销代价极高
删数据 / 对外公告永不授权不可撤回 + 舆情风险

人工兜底节点的设计要点
  • 确认界面要“一眼能判”：AI 提议发券时，给人工看的卡片要包含：客人诉求、AI 的理由、金额上限——3 秒能决策，否则兜底变成新瓶颈。
  • 兜底动作留痕：谁确认、何时确认、确认内容，全部落日志——出了纠纷能回溯，这也是团队信任 AI 的基础。
  • 额度内放权：20 元以内的券可以免确认（写死上限），超了才进人工——安全和效率不是零和，额度设计就是平衡点。
📌 本节要点
  • 授权判据：错了能撤回吗？能→自动；有代价→人工确认；撤不回→永不授权。
  • 资金动作零授权：改价、退款、转账、删数据，永远在人手里。
  • 兜底要好判、留痕、有额度：3 秒决策界面 + 全程日志 + 小额免确认。
  • 权限表写进 SOP：团队共用一份，别每个 Agent 各自为政。
